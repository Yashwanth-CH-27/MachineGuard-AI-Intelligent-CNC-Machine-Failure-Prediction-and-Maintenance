## Not verified and should not be claimed

- **Windows `.bat` double-click execution:** this project was authored and tested in Linux, so native Windows BAT, Python discovery, venv creation, dependency install, browser opening and Ctrl+C shutdown were **not run on a Windows machine**.
- **Live Streamlit UI/browser smoke test:** Streamlit was **not installed in this sandbox**, so the complete actual rendered pages and browser widgets were not launched and visually verified. Python UI files were syntax-checked; underlying ML, history and report behaviors have test coverage.
- **Official UCI 2020 CSV download:** network fetches are blocked in this build environment. The optional download/retrain code is implemented but its remote retrieval has **not** been successfully executed here.
- **GitHub web upload and CI workflow:** included instructions and `.github/workflows/tests.yml` were not run in a real GitHub account. No repository or Excel submission has been created.
- **Industrial sensor connectivity or real machine validation:** not implemented, not claimed.

## Windows-specific verification checklist for the reviewer

1. On Windows 10/11, install Python 3.10–3.13 (check `py -3 --version` or `python --version`) and provide internet for first-run pip installation.
2. Extract the ZIP in a writable folder and double-click `START_PROJECT.bat`. Confirm a `.venv` was created and the script starts Streamlit at `http://localhost:8501`.
3. Confirm the app identifies whether the model uses the included simulator or UCI AI4I 2020 downloaded synthetic records. On an offline first launch, ensure failure to obtain UCI is nonfatal (pip packages must already be installed).
4. Open all five pages and exercise single inspection, sample CSV batch upload, chart rendering, and both report downloads.
5. Deliberately upload a CSV with invalid headers; confirm the app shows an understandable validation error.
6. Stop the server with Ctrl+C; restart it and confirm packages and matching model are reused.
7. Compare the Model Intelligence tab to `models/training_results.json`; no synthetic metrics should be presented as real industrial performance.

Model fitting and metrics were generated by an actual training execution, not invented. Re-running after dependency updates may change scores. A joblib model trained with a different scikit-learn version is automatically retrained at startup if it is not compatible; only load trusted model artifacts.
